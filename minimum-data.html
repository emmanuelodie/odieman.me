If your data has this, the analysis stands

Before a figure reaches a committee, it should be clear that the data could support it. For each tool, this page lists the files it reads, what each analysis needs, and the smallest numbers it will report on. Each tool carries the same list on its own Minimum data page, with Check my data, which reads the data loaded and marks every analysis as ready, limited or not possible, with the reason and what to add.

How Check my data decides

VerdictMeaningExample from the sample hospital
ReadyThe data loaded has what the analysis needs, at the size the method asks for.AMS Pro, antibiogram: 579 first isolates; 56 of 98 organism–antibiotic cells reach 30 isolates (the cells that do not are flagged, not hidden).
LimitedThe analysis runs, but part of the data is missing or small, and the result must be read with that in mind.PPS Pro, ward feedback: one ward has fewer than 10 patients, so its percentages change a lot with one patient.
Not possibleA file or a column the analysis cannot do without is missing. The tool says which, instead of showing a weak figure.Any analysis whose essential file has not been loaded.
OptionalAn extra that adds an analysis but is not needed for the others.AMS Pro, C/S Prophylaxis Project: needs the Surgery Patients Report.

The check reads the data on screen, every time. The same check is printed in each tool's reports (Data used and its limits), so a reader of the report sees what the figures rest on.

AMS Pro

Afya eHMS exports work as they are: CSV or Excel, title rows above the header skipped, several files dropped together. The one rule that matters most: ward names in the admissions file must be written exactly as the department names in the dispensing file.

PPS Pro

One row is one inpatient present at 08:00 on the survey day, treated or not. CSV or Excel; REDCap raw-data exports and Stata files with these names are read too, and the WHO PPS data-entry tables are recognised by their own column names. A REDCap data dictionary builds a matching project.

NeedColumns
Essentialsurvey_id, survey_date, ward, on_antimicrobial (Y or N for every inpatient: the denominator), and ab1_name, ab2_name… for each antimicrobial of a treated patient
Recommendedward_type, patient_code (anonymous, never the hospital number), age_years, sex, admission_date, diagnosis, indication, reason_in_notes, guideline_compliant, culture_taken, stop_review_date, and for each antimicrobial its route, dose in mg and doses per day
OptionalFacility, ward code, weight, WHO risk factors, treatment type, biomarker, appropriateness and its reasons, ATC code and AWaRe group (filled from the reference list when blank)

Rules for every file

  • No names. Use patient numbers or anonymous study codes. A survey file never carries the hospital or registration number.
  • Dates as YYYY-MM-DD, day/month/year (05/02/2026 is 5 February), or Excel dates.
  • The same months in every file, and the same ward names and patient IDs across files.
  • One export per period, as the system produced it, not edited or sorted by hand.
