PPS Pro

A WHO-methodology point prevalence survey tool that works with the data Tanzanian hospitals really have: type patients in at the bedside, or start from the pharmacy and admission exports and the WHO PPS tables — then check every prescription against the Tanzania STG, give each ward its own feedback, and follow every indicator across survey rounds with formal trend tests.

Showcase (3.10)

A stage for a talk (★ Showcase in the top bar, in the live demo too). PPS Pro opens empty; the sample hospital's survey files go in one by one, the counts rise on an assembly line, and a ledger shows that rows in = rows used + rows set aside. Each headline figure starts red, naming the file it still needs, and turns green when that file arrives. Then Reports, one click writes real files from the data just loaded: the WHO PPS worksheet and the WHO files one CSV per level, the REDCap import file and data dictionary, the two Stata files, the trend report and the indicator table. It ends on decisions for the AMS committee and for management. Every figure on the stage is read from PPS Pro after it has done the work. Keys: → next, ← back, 1–8 the outputs, F full screen, Esc opens the tool; a presentation clicker works. It runs fully offline with Odieman_Sample_Hospital.js beside the tool, and in a full copy it can also run on the data loaded now (your own, nothing saved) or on files dragged onto the stage.

Minimum data and Check my data (3.6)

A page in the Start menu that says what PPS Pro needs for each analysis: every column, the headings it also accepts, the smallest numbers it will report on, and blank templates. Check my data reads the survey on screen and marks each analysis ready, limited or not possible, with the reason. The trend report ends with the same check, under Data used and its limits. No figure changed. The minimum data for PPS Pro.

Stata, both ways (3.5)

The Stata page (Output menu) writes one survey or all surveys as Stata data files (.dta, Stata 14 or later): a patients file and an antimicrobials file, every variable and code labelled from PPS Pro's own code lists, with as many antimicrobial columns as the busiest patient needs. Import reads Stata files back (Stata 13 or later). The files were read back correctly by two independent readers, pandas and ReadStat (the reader R's haven uses); a test in Stata itself is still to come.

Manual entry on any form (3.8)

Fill in PPS Pro's own form, or load any REDCap project's data dictionary and fill in that project's form instead, with its branching logic. Send the entries to a plain CSV, a REDCap import file or a labelled Stata file, or straight into a survey here.

Decision brief (3.9)

One printable page for a committee that will not read the full report: what was measured, the headline figures exactly as the tool shows them, whether the data meet the minimum, what it means in plain words, and a question for the committee to decide.

Sample hospital and Present (3.7)

One click opens five simulated surveys in memory, without internet and without touching your own data. Present runs a seven-stop guided tour with large text for a projector; every figure a caption says is read from the screen it shows.

The exact 95% value

Every confidence interval now uses z = 1.959963984540054 rather than a rounded 1.96. No figure on screen changes at the precision shown, and Stata's own commands now match PPS Pro exactly.

Built for REDCap

Collect in REDCap and analyse here: PPS Pro writes the REDCap data dictionary from its own code lists, so a project built from it always matches the tool, and the project's export as CSV (raw data) opens in PPS Pro as it is. Or move a survey from PPS Pro into REDCap: PPS Pro writes a file for REDCap's Data Import Tool, one record per inpatient. Tested so far with simulated REDCap files; a test in a live REDCap project comes next.

Four antimicrobials on the REDCap form

PPS Pro keeps every antimicrobial a patient has. The REDCap form holds four, so a patient on more keeps only the first four in REDCap. The REDCap page warns about this before you write the file.

Data dictionary corrected

Seven labels in the 3.3.2 dictionary had lost their “&” or “–” (for example “Obs Gyn” for “Obs & Gyn”). The codes were right, so data collected with it imports the same way. The 3.4 files carry the correct labels.

New in version 3.3.2

November 2026. Changes that let PPS Pro work beside other survey tools. Figures from earlier surveys are unchanged.

Reads REDCap exports

A REDCap project built from the PPS Pro data dictionary exports its data as CSV (raw data), and PPS Pro opens that file as it is. Groups already running point prevalence surveys in REDCap can analyse them here. See the data dictionary and REDCap file.

Every antimicrobial kept

A patient on more than four antimicrobials keeps them all, on Data entry and in every export.

Fixes

An inhaled route in an imported file stays inhaled. Charts no longer stop when an indicator has no data in any survey. The report sentence on the Access share is judged on the share as printed, against the UN 2030 target of 70%.

New in version 3.3

Built after a review of the leading survey tools — WHO PPS, Global-PPS and Australia's NAPS — keeping what fits a Tanzanian hospital and leaving out what needs an IT department.

Reads real hospital files

Excel as well as CSV; the WHO PPS data-entry tables (Patient, Indication, Antibiotic — as separate files or one workbook, several surveys split automatically); and Afya eHMS pharmacy and admission reports, even when the patient columns have no headings. Only what a survey can use is kept — non-antimicrobial items, eye and skin preparations, broken rows, names and insurance numbers are dropped — and every correction (swapped day and month, merged ward-code spellings) is listed for review, never made silently.

Optional pre-fill from pharmacy and admissions

From the exports, PPS Pro adds the inpatients present at 08:00 on survey day with their antimicrobials, dose, route and frequency, and prints a bedside worklist for what only the chart shows. A readiness check says plainly what the files can and cannot give a survey. Patients not on an antimicrobial are kept only as a count for the denominator. Typing patients in by hand works exactly as before.

Guideline check against the Tanzania STG

Each patient's antimicrobials are compared with the regimens in the STG/NEMLIT 2021 for the diagnosis, age group and indication — 56 rules, each citing its section and page. Where the STG gives no regimen (neonatal sepsis and meningitis, surgical prophylaxis outside obstetrics), clearly labelled WHO rules are used instead. It is a suggestion: the surveyor decides. A newer STG edition can be loaded as a rules file.

Type the drug, the tool does the rest

Write the name as it appears on the chart or pharmacy list (“Ceftriaxone 1g IV”, “amoxyclav”, “metronidazol”). PPS Pro fills in the ATC code, the WHO DDD and the AWaRe group, and asks “Did you mean…?” when it is not sure. AWaRe is shown both ways, WHO and the Tanzania STG/NEMLIT 2021 list, checked against each other. The national group is followed where it is stricter and the book's own level of care supports it (meropenem, amikacin and vancomycin as Reserve). Where the book contradicts itself (gentamicin and cotrimoxazole printed as Watch, yet stocked at every dispensary) or is less strict than WHO, WHO wins, and the tool shows the page and the reason. The WHO export always uses WHO.

Deeper analysis

Adults, children and neonates reported separately; surgical prophylaxis by duration, ward type and agent; empiric versus culture-targeted treatment and biomarker use; appropriateness in NAPS categories (optimal, adequate, suboptimal, inadequate) with reasons; and the survey set beside published Tanzanian point prevalence surveys, with full references.

One-page feedback for every ward

Each ward in-charge gets their own results next to the hospital and their previous survey, what stands out, what is going well, and space for the actions agreed at the ward meeting. No patient or prescriber is named.

Survey quality you can show

Practice cases for every surveyor (80% to pass, as NAPS requires) and an agreement check: a second surveyor re-surveys one patient in ten, and PPS Pro reports percent agreement and Cohen's kappa field by field.

How a survey runs

1. Prepare

Surveyors complete the practice cases. Ward names and WHO ward types are set once. If the pharmacy and admission exports are available, pre-fill the survey and print the bedside worklist.

2. Survey day

On each ward, every inpatient present at 08:00: confirm or enter the antimicrobials, and record diagnosis, indication, reason in notes, guideline compliance (with the STG check beside it), culture, stop/review date, empiric or targeted, biomarker and appropriateness. Patients not on antimicrobials only need counting. Several surveyors' files merge into one survey.

3. Data quality

Duplicate codes, missing ward or age, admission after the survey date, hospital-acquired infection within 48 hours, prophylaxis without surgery, targeted treatment without a culture, unchecked pre-filled patients, and every correction made on import — checked automatically. A 10% re-survey list and the agreement report show how reliable the data are.

4. Results

Prevalence with a Wilson 95% confidence interval, AWaRe mix, the new analyses above, ward-by-ward results, and every indicator across rounds with a Cochran–Armitage test for trend — in a printable trend report, the WHO PPS export format, and one feedback sheet per ward.
