How every release is checked

A tool that a committee acts on has to give the same answer tomorrow that it gave today, and a new feature must not quietly change an old figure. So no version is released on the strength of its own output. Each one is compared with the version before it, and every new calculation is worked out a second time, separately. What has not been tested yet is said plainly.

Four checks on every release

1. Against the version before

The same data is loaded into the new version and the old one, and every page, figure and export is compared. Only the intended changes may differ, and each of those is shown before and after. Everything else must be identical, down to the look of each unchanged page.

2. A second, independent calculation

Where a feature produces a number, the number is worked out again outside the tool, from the written method rather than from the tool's code: in Python, with statsmodels for the time-series models, and with two separate readers (pandas and ReadStat, the reader R uses) for every Stata file. REDCap files are checked against REDCap's own import rules. The tool's arithmetic is never used to check itself.

3. The real screens, end to end

An automated browser opens the actual tool file and does what a user would: imports files, fills in forms, presses the buttons, downloads the reports and opens them again. Errors on the page fail the check.

4. The website demos

Each live demo is made from the full version by one script, which rebuilds the demos already online byte for byte before it is trusted with a new one. The demo lock (no files of your own can be opened in a demo) is tested on every build, and the guided tour is run from the website itself.

Found and fixed by checking

  • AMS Pro: an operation recorded in both the procedures report and the admissions register was counted twice, so every prophylaxis prompt appeared twice. Found while building the story page; fixed in October 2026.
  • PPS Pro 3.4: seven labels in the published data dictionary had lost an “&” or a dash. The codes were right; the corrected files are on the technical page.
  • Manual entry: a value typed into a field later hidden by the form's branching logic could still reach an export. Hiding a field now clears it everywhere.
  • VigiWard sample hospital: some simulated pharmacist reviews did not agree with their own causality scores, and they dismissed the planted bad batch of ceftriaxone. They were rewritten so every review is consistent with its WHO-UMC category and Naranjo score, before this update went online.

Not tested yet

Said here so that nobody has to find it out.

  • REDCap: PPS Pro's and VigiWard's REDCap files have been tested with simulated files against REDCap's import rules, not yet in a live REDCap project.
  • Stata: every Stata file was read back correctly by two independent readers, and AMS Pro's model was re-run from its files outside Stata; the files and command files have not yet been run in Stata itself.
  • WHONET: the WHONET-ready files follow the BacLink guides on whonet.org; the import has not yet been tried in BacLink.
  • The new features on real hospital data: everything above was checked on the simulated sample hospital. The tools themselves have been used with real data at a regional referral hospital; the November 2026 additions have not yet.
