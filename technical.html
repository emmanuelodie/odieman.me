What the tools read, keep and produce

For the hospital ICT officer, the hospital-system team, the reviewer and the partner organisation: what each tool needs from your hospital system, where it keeps its data, what it hands back, and the one connection it can make. Written from the tools' own code. The statistics behind the figures are on the methodology page.

How a tool runs

The same five steps in all three tools. Every step happens inside the browser on the computer in front of you.

Your exportExcel or CSV from the hospital system
→
The toolreads, classifies, links, calculates
→
Your data folderdatabase, backups, exports, reports

No server in the middle. No upload. The export never leaves the computer.

1. Open

Open the HTML file in Chrome or Edge. If a data folder was chosen before, the tool asks the browser for permission to use it again (one click after a browser restart) and loads the saved database from it. The browser remembers which folder was chosen; the tool cannot see any other folder.

2. Import

You choose the export files. Excel workbooks are unpacked in the browser and CSV files read directly. AMS Pro and VigiWard find the header row automatically near the top of the sheet, so title rows above it are skipped; AMS Pro matches column names without regard to capitals, spaces or punctuation. PPS Pro (3.3) reads its own CSV layout, the same layout in Excel, the WHO PPS data-entry tables (Patient, Indication, Antibiotic, Ward, Hospital — separate files or one workbook), and — for the optional pre-fill — Afya eHMS pharmacy dispensing and admission reports, finding the header row under report titles and recognising unlabeled patient columns by their content. Names, prescriber names, payment and insurance numbers in those reports are never read into the tool.

3. Classify & link

Each item name is matched to its generic name, WHO AWaRe group, ATC code and WHO DDD from the reference list built into the tool (or the newer list you applied). Files are linked by patient ID; in AMS Pro, dispensing is linked to bed-days by ward name.

4. Calculate

Indicators, trends, control charts, signals and tests run in the browser's memory. The methods are set out on the methodology page.

5. Save & report

Every change is written to the data folder automatically, with a daily backup. Word, PowerPoint, CSV, XML and other files are made in the browser and saved into the folder's reports/ or exports/, or downloaded when no folder is open.

Where the data is kept

In Chrome or Edge, each tool keeps its work in a folder the user picks once, on their own computer. The folder is laid out the same way every time and carries a README.txt explaining it. The browser's own storage keeps working alongside the folder.

AMS Pro

AMS_Data/ (any name, chosen by the user) odieman_ams_pro_data.json main database, rewritten about half a second after each change backups/ one copy per day (last 30) + a safety copy before any reset, erase, restore or snapshot load exports/ CSV and JSON exports reports/ Word (.docx) and PowerPoint (.pptx) reports snapshots/ named snapshots, e.g. one per ward or reporting period README.txt

PPS Pro

PPS_Data/ odieman_pps_data.json main database (all surveys) surveys/ one CSV per survey, rewritten whenever that survey changes backups/ daily copy of the database (last 30 by default; set on Settings) reports/ reports, charts and exports *.csv new survey files dropped here are imported when the tool opens README.txt

VigiWard

VigiWard_Data/ vigiward_data.json signals, review decisions, Naranjo and TMDA-reported marks, detection settings, data-quality report, cardiometabolic profile datasets/ the de-identified imported datasets (pharmacy, lab, deaths, readings), reloaded next time so nothing is re-imported backups/ daily copy (last 30), safety copies, and the previous datasets before an import replaces them (backups/datasets/) exports/ CSV and Excel exports reports/ TMDA report, E2B XML, RTF reports, manuscript drafts README.txt

Rules that protect the data

  • Nothing is overwritten unread. In AMS Pro and VigiWard, when the browser copy and the folder copy differ, the newer one is used (or the user chooses) and the other is written into backups/ first. PPS Pro merges the two survey by survey, keeping the most recently changed version of each.
  • No half-written files. In AMS Pro and VigiWard, writes run one at a time and each file is swapped in only once it is completely written, so a power cut mid-save leaves the previous file intact.
  • Real patient identities stay out of VigiWard's folder. Real patient IDs, names and initials are held in memory only, for the TMDA form in that session; the saved datasets carry the P_XXXX codes.
  • Without a folder (or in a browser other than Chrome or Edge), AMS Pro and VigiWard keep their data in the browser's local storage, which holds only about 5–10 MB (VigiWard keeps only its top 2,000 signals there). PPS Pro keeps its surveys in the browser's IndexedDB. In this case, download a backup after each working session.
  • Moving to another computer: copy the whole data folder together with the tool's HTML file, open the tool in Chrome or Edge and choose that folder. Its data opens straight away.

The reference list file

WHO revises the AWaRe classification every two years and the ATC/DDD Index every year. One file, published on the reference list page, carries the new lists to every copy of the tools. On a computer with no internet, the same file can be brought on a flash drive and opened with Load update file.

A file that fails any check is refused as a whole, and the tool lists the problems it found. Before applying, each tool shows what would change for it and for the data already loaded (for example, how many dispensing lines would change AWaRe group). The list in use is saved with the tool's data, so a report can be re-run on the same list later, and Go back to the built-in list undoes the update at any time. Requirements and limits

  • Browser: Google Chrome or Microsoft Edge on a desktop or laptop. Saving to a data folder needs one of these two. Other browsers open the tools, but keep data in browser storage only.
  • Computer: any hospital PC that runs Chrome or Edge. Nothing is installed, so no administrator rights are needed.
  • Internet: not needed to use the tools. The live demos on this website need it, and are best on a laptop.
  • Data volume: three years of AMS Pro data is about 14 MB, more than browser storage alone holds, so open a data folder before importing more than a few months.
  • Large exports: CSV reads much faster than Excel for very large files.
  • Files per type: AMS Pro merges several files per type (for example one per year); VigiWard reads one file per type, so export the whole period at once; PPS Pro takes one CSV per survey.

Versions and updates

Current versions: AMS Pro 4.9, PPS Pro 3.3 and VigiWard 3.9. Each tool shows its version on screen.

  • Reference lists (AWaRe groups, ATC codes, DDDs) are updated through this website, without a new copy of the tool. See the reference list page.
  • Fixes and new versions are sent to registered holders. Each licensed copy is registered to its facility, which is how news of updates reaches it. Request the tools.
